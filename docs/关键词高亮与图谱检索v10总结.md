# 关键词高亮与图谱检索 v10 总结

> 课程 58 · 代码基线 `ai-agent-code/knowledge/knowledge-hub-backend`（v10）
> 整理时间：2026-11-04

## 一句话

**索引从「写得进」升级到「查得出」**：补上 `POST /search`（ES 全文 + IK + 高亮）和 `GET /graph/*`（Neo4j 节点/边/关键词检索）两个在线入口，同时把 Search 链路从「消息带快照」改成「只带 ID 回查全文」。

## 两个在线入口

| 入口 | 接口 | 数据源 | 鉴权 |
|---|---|---|---|
| 全文检索 | `POST /search` | ES `kh_document` | `@RequirePermission('search')` |
| 图谱检索 | `GET /graph/search`、`/graph/nodes`、`/graph/edges` | Neo4j | 仅需登录 |

## Search 链路被反转（本讲关键改动）

| | v4 / v5 做法 | v10 做法 |
|---|---|---|
| 消息内容 | 文档快照（正文截 1000 字） | **只带 `documentId`** |
| 消费端 | 直接写 ES，不回查 | 回查 Postgres + Mongo 拿**全文** |
| 索引新鲜度 | 改正文后索引陈旧 | 反映最新正文 |
| 召回完整性 | 1000 字后的词搜不到 | 全文可搜 |
| 代价 | MQ 报文大 | 消费时多一次 DB 读 |

配套删除：`buildSearchIndexData()`（组快照）整段删除，`afterPublish(doc)` 不再传 content。

## ES 索引与 IK 分词

```ts
// 写入细切、检索粗切
const ikText = { type: 'text', analyzer: 'ik_max_word', search_analyzer: 'ik_smart' };
```

`ensureEsIndex()` 三段逻辑：

1. 索引不存在 → 按 mapping 创建（`title/summary/content` 用 IK，`id/tags/categoryId/authorId` 用 keyword）；
2. 已存在且 `title.analyzer === 'ik_max_word'` → 直接返回；
3. **已存在但未配 IK → 删除重建**并 warn「请重新发布文档」。

## 检索查询结构

```ts
multi_match: {
  query: keyword,
  fields: ['title^3', 'summary^2', 'content'],   // 标题 > 摘要 > 正文
  analyzer: 'ik_smart',
}
// 有筛选时包一层 bool：
{ bool: { must: [multi_match], filter: [{ term: { categoryId } }, ...] } }
```

- `filter` 只筛不打分，性能优于塞进 `must`；
- `_source: { excludes: ['content'] }` 列表不回传全文，但仍参与匹配与高亮；
- `highlight`：`title` 整段（`number_of_fragments: 0`）、`content` 160 字 × 3 段、`summary` 120 字 × 1 段；
- `pageSize` 上限 50（`Math.min`），ES 不可用时返回空分页而非抛错。

## 图谱检索

| 方法 | 接口 | 说明 |
|---|---|---|
| `searchGraph` | `GET /graph/search?keyword=&limit=` | 关键词搜节点，返回 DocumentChunk / KnowledgeEntity 混排 |
| `listNodes` | `GET /graph/nodes?type=&limit=` | 实体节点列表，可按键类型过滤 |
| `listEdges` | `GET /graph/edges?limit=` | `RELATED_TO` 边 |

关键 Cypher 技巧：

```cypher
WHERE toLower(coalesce(n.name,''))  CONTAINS toLower($kw)
   OR toLower(coalesce(n.title,'')) CONTAINS toLower($kw)
   ...
RETURN labels(n)[0] AS label,
       coalesce(n.name, n.title, n.heading, n.id, n.chunkId) AS name,
       CASE WHEN n.content IS NULL THEN null ELSE substring(n.content, 0, 160) END AS snippet
```

**必须 `coalesce` 再 `toLower`**：文档节点用 `title`、实体用 `name`、块用 `chunkId`，`null` 参与 `CONTAINS` 会恒为假。

## 权限与审计收紧

1. 新增 `PermissionCode` 常量：`documentList / documentCreate / documentEdit / documentDelete / documentReview / search`。
2. `document.controller` 每个接口补 `@RequirePermission(...)`，`search` 用 `'search'`。
3. 所有写操作改为 **必传 `actor: AuthUser`**：`authorId / createBy / updateBy` 一律取自 `actor.userId`。
4. **DTO 删除 `authorId` / `createBy` / `updateBy`** —— 不允许客户端伪造作者。

## 关键设计

1. **索引与检索解耦**：写侧只在发布时触发一次，读侧随时可用；ES 挂掉检索降级为空列表，不影响发布。
2. **IK 双 analyzer**：写入细粒度（召回高）、检索粗粒度（更准）。
3. **字段权重**：`title^3 / summary^2 / content` 体现「标题命中更重要」。
4. **列表不返回全文**：靠 `_source.excludes` + `highlight` 控制响应体大小。
5. **所有筛选走 `filter`**：不参与打分、可缓存，避免污染相关性。
6. **图谱读接口复用 `GraphBuildService`**：不为查询新建 service，PipelineModule 直接 export。

## 易错点

| 坑 | 说明 |
|---|---|
| ES mapping 变更 | `ensureEsIndex` 会**删索引重建**，历史文档必须重新发布才能搜到 |
| 索引刚建就搜 | 写入用 `refresh: true` 才立即可见；批量导入应关掉再手动 refresh |
| `MATCH (n)` 全图扫描 | 小图可用，大图必须加 label 约束或改用 Neo4j 全文索引 |
| 高亮 vs `_source` | `excludes` 只影响返回体，**不影响匹配与高亮** |
| DTO 删字段的连锁 | 前端若还传 `authorId`，会被 `forbidNonWhitelisted` 拒绝 |
| graph 接口是 GET | 用 POST 打会返回 `Cannot POST /graph/search` |
| 权限码未配 | 普通用户调 `/search` 会 403（admin 自动拥有 `search`） |

## 验收

```bash
TOKEN=$(curl -s -X POST localhost:3000/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"123456"}' | jq -r .accessToken)

# 发布（触发三路索引）
curl -X PUT "localhost:3000/documents/$DOC_ID/publish" -H "Authorization: Bearer $TOKEN"

# 全文 + 高亮（POST）
curl -s -X POST localhost:3000/search -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"keyword":"差旅报销","page":1,"pageSize":10}' | jq '.items[0].highlight'

# 图谱（GET）
curl -s "localhost:3000/graph/search?keyword=财务部&limit=20" -H "Authorization: Bearer $TOKEN" | jq
curl -s "localhost:3000/graph/nodes?limit=50" -H "Authorization: Bearer $TOKEN" | jq 'length'
```

## 主动回忆

1. **为什么把「消息带快照」改成「只带 ID 回查」？**
   快照截断 1000 字导致后文搜不到；正文修改后索引陈旧。回查能拿全文与最新版本，代价是消费时多一次读。

2. **IK 为什么写入用 `ik_max_word`、检索用 `ik_smart`？**
   写入细切 → 索引里词项多，召回高；检索时细切会产生大量无意义组合，粗切命中更准。这是中文检索的常规搭配。

3. **为什么筛选要用 `filter` 而不是 `must`？**
   `filter` 不参与打分、结果可缓存，且不污染 BM25 相关性；`must` 会影响 `_score`。

4. **Cypher 里为什么必须先 `coalesce` 再 `toLower`？**
   三类节点字段名不同（`name`/`title`/`chunkId`），`null` 参与 `CONTAINS` 结果为 `false`，直接用 `n.name` 会让文档节点永远匹配不到。
